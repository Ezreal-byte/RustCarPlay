# RustCarPlay v0.1.1

## 中文

本轮提供包含媒体运行时和实验认证材料的**桌面安装包预览**，普通启动无需另装开发工具或 GStreamer，也无需手填认证目录。新包的 CI 与安装环境验证仍在进行，实际可用资产以 Release 和工作流结果为准。

- **Windows：**运行 `RustCarPlay-0.1.1-windows-x86_64-setup.exe`，按当前用户安装，无需管理员权限；从开始菜单启动。
- **macOS：**打开对应 Intel/Apple Silicon 的 DMG，将 RustCarPlay 拖入 Applications。目前仅供 GUI/核心预览，不能连接 CarPlay。
- **Ubuntu 24.04：**使用 `sudo apt install ./rustcarplay_0.1.1_amd64.deb`；ARM64 使用 `arm64` 文件，安装后从应用菜单或 `rustcarplay` 启动。缺少的系统依赖由 apt 安装，可能需要网络。

ZIP/TAR 便携包继续提供，完整解压到可写目录后启动根目录 `RustCarPlay.exe` 或 `./RustCarPlay`。安装版将个人数据保存在 Windows `%LOCALAPPDATA%\RustCarPlay\.local\`、Linux `$XDG_DATA_HOME/rustcarplay/.local/`（默认 `~/.local/share/rustcarplay/.local/`）、macOS `~/Library/Application Support/RustCarPlay/.local/`；卸载保留数据。便携版在解压目录生成 `.local/`。这些设置、配对和日志不随包发布。

根入口是轻量启动器；桌面程序和 CLI 位于 `app/`，媒体库和插件位于 `runtime/gstreamer/`，Windows USB 用户态依赖位于 `runtime/usb/` 与 `runtime/usb-filter/`，固定实验身份和来源记录位于 `resources/auth/`。启动器只配置子进程环境，使用 `--cli` 可进入命令行；安装版通过 `INSTALLATION.json` 选择用户数据目录。

**实验身份说明：**材料来自固定 DiPlay v0.2.15 预览 APK，上游声明来自 Carlinkit C2Air / Allwinner V821 公开固件。这不是新签发的身份，不适用项目源码 GPL；公开下载、提取或选择此预览分发都不构成权利人的再分发许可。分发适用性与未来 iOS 接受情况仍未确定。来源和限制保存在 `resources/auth/provenance.json`；认证私钥不进入 Git 或 Rust 源码包。详见[第三方声明](../THIRD_PARTY_NOTICES.md)。

平台边界：

- **Windows 11 x64：**建议先用局域网模式，电脑和 iPhone 加入同一 Wi-Fi 并在系统完成蓝牙配对，无需在应用输入 Wi-Fi 密码。既有开发版本与一台 iPhone 的无线/USB 画面、触控和声音，以及 USB 暂停与重连已初测正常；这不等于新离线包已完成干净系统验收。
- **Windows USB：**包内 DLL 不替代 Apple Mobile Device Service、手机信任、权限和设备驱动配置。另提供 `runtime/usb-driver/libusb-win32-bin-1.4.0.2.zip` 过滤驱动资源，供准备脚本优先读取，绝不自动安装；原有摘要/签名校验与恢复流程不变。Apple 服务和 UsbNcm 系统驱动不带。准备仍依赖 PowerShell 7 与 SDK 签名验证工具，并可能需要手动重插。驱动备份仍在安装根 `.local/windows-usb/`，卸载会保留但不会还原驱动；需要撤销时先按[驱动配置与恢复](../WINDOWS_USB_DRIVER.md)处理，并保留备份目录。
- **Linux x64 / ARM64：**Ubuntu 24.04 / glibc 2.39 基线，自带所选媒体依赖闭包。BlueZ、NetworkManager、usbmuxd 等声明依赖由系统包管理器提供；桌面、硬件驱动、音频服务和设备权限仍需系统配置。真机未验收。
- **macOS Intel / Apple Silicon：**macOS 15 GUI/核心预览，采用 ad-hoc 签名且未公证。原生 RFCOMM、USB、网络适配未实现，不能完成接收端连接。
- **Android / HarmonyOS：**本轮不构建移动端；桥接与系统适配仍待实现，见[后续移植方案](../MOBILE_PORTING.md)。

20 次连接循环、两小时稳定性、Siri/通话、音频设备切换与休眠恢复仍待验收。硬件解码、完整第二屏、P2P、AEC、停车视频和车辆扩展未交付。本轮离线打包不扩大既有[验收范围](../ACCEPTANCE.md)。

## English

This release provides **desktop installer previews** with media runtimes and experimental authentication material included. Ordinary launch needs no separately installed development tools or GStreamer and no manual certificate path. CI and installation validation are still in progress; check the actual Release and workflow results for available assets.

- **Windows:** run `RustCarPlay-0.1.1-windows-x86_64-setup.exe`; installation is per-user and requires no administrator privileges. Open the app from Start.
- **macOS:** open the Intel/Apple Silicon DMG and drag RustCarPlay to Applications. GUI/core preview only; CarPlay connections are unavailable.
- **Ubuntu 24.04:** run `sudo apt install ./rustcarplay_0.1.1_amd64.deb` (use `arm64` for ARM64), then launch from the application menu or `rustcarplay`. Apt installs missing system dependencies and may need network access.

Portable ZIP/TAR archives remain available. Extract the entire archive into a writable directory and run its root `RustCarPlay.exe` or `./RustCarPlay`. Installed applications keep personal data in Windows `%LOCALAPPDATA%\RustCarPlay\.local\`, Linux `$XDG_DATA_HOME/rustcarplay/.local/` (default `~/.local/share/rustcarplay/.local/`), or macOS `~/Library/Application Support/RustCarPlay/.local/`. Uninstalling preserves that data. Portable applications use `.local/` inside the extraction directory. Personal settings, pairings and logs are never shipped.

The thin root launcher configures only its child process. `app/` contains the desktop program and CLI; use `--cli` for the latter. Media libraries/plugins are under `runtime/gstreamer/`, Windows USB user-space libraries under `runtime/usb/` and `runtime/usb-filter/`, and experimental authentication material under `resources/auth/`. An `INSTALLATION.json` marker selects the installed user-data layout.

**Experimental identity:** the fixed DiPlay v0.2.15 preview APK supplies this material, attributed upstream to public Carlinkit C2Air / Allwinner V821 firmware. It is not newly issued and is outside the source-code GPL. Public availability, extraction and choosing this preview distribution do not establish permission from the rights holder. Redistribution suitability and future iOS acceptance remain unresolved. `resources/auth/provenance.json` records the source and limitations; Git and Rust source archives exclude authentication private keys. See [third-party notices](../THIRD_PARTY_NOTICES.md).

- **Windows 11 x64:** start with LAN, the same Wi-Fi and OS Bluetooth pairing. No in-app Wi-Fi password is needed. Existing development builds passed initial wireless/USB video, touch and audio tests with one iPhone, plus USB pause/reconnect. This does not certify the new offline archive on a clean machine.
- **Windows USB:** still requires Apple Mobile Device Service, trust, permissions and device configuration. `runtime/usb-driver/libusb-win32-bin-1.4.0.2.zip` is included for preparation scripts to use first; it is never installed automatically. Existing hash/signature checks and recovery remain unchanged. Apple services and UsbNcm are not bundled. Preparation needs PowerShell 7/SDK signature tools and may require a physical replug. Driver backups remain in `.local/windows-usb/` under the installation directory; uninstalling preserves them but does not restore drivers. Follow [configuration and recovery](../WINDOWS_USB_DRIVER.md) first when undoing device setup, and retain the backup directory.
- **Linux x64 / ARM64:** Ubuntu 24.04 / glibc 2.39 baseline with the selected media dependency closure. Declared dependencies such as BlueZ, NetworkManager and usbmuxd come from the OS package manager. Desktop services, hardware drivers, audio services and permissions still need system configuration. No physical-device acceptance yet.
- **macOS Intel / Apple Silicon:** an ad-hoc-signed, non-notarized macOS 15 GUI/core preview. Native RFCOMM, USB and network adapters are missing; receiver connections are unavailable.
- **Android / HarmonyOS:** not built in this release; bridges and platform adapters remain planned. See the [porting roadmap](../MOBILE_PORTING.md).

Twenty connection cycles, two-hour stability, Siri/calls, audio device switching and sleep recovery remain unverified. Hardware decoding, full second-screen support, P2P, AEC, parked video and vehicle extensions remain unfinished. Offline packaging does not extend the recorded [device acceptance](../ACCEPTANCE.md).
