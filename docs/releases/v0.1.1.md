# RustCarPlay v0.1.1

## 中文

本轮将 v0.1.0 的程序加外部运行时方案改为**完整离线包预览**：完整解压后启动根目录 `RustCarPlay.exe`（Windows）或 `./RustCarPlay`（Linux/macOS），普通启动无需安装 Rust、Python、PowerShell 或 GStreamer，也无需手填认证目录。新包的 CI 与环境验证仍在进行，实际可用资产以 Release 和工作流结果为准。

根入口是轻量启动器；桌面程序和 CLI 位于 `app/`，媒体库和插件位于 `runtime/gstreamer/`，Windows USB 用户态依赖位于 `runtime/usb/`，固定实验身份和来源记录位于 `resources/auth/`。Linux 的用户态连接库随媒体依赖闭包打包。启动器只配置子进程环境；使用 `--cli` 可进入命令行。个人设置、配对、媒体缓存和日志在运行时写入本地 `.local/`，不随包发布。

**实验身份说明：**材料来自固定 DiPlay v0.2.15 预览 APK，上游声明来自 Carlinkit C2Air / Allwinner V821 公开固件。这不是新签发的身份，不适用项目源码 GPL；公开下载、提取或选择此预览分发都不构成权利人的再分发许可。分发适用性与未来 iOS 接受情况仍未确定。来源和限制保存在 `resources/auth/provenance.json`；认证私钥不进入 Git 或 Rust 源码包。详见[第三方声明](../THIRD_PARTY_NOTICES.md)。

平台边界：

- **Windows 11 x64：**建议先用局域网模式，电脑和 iPhone 加入同一 Wi-Fi 并在系统完成蓝牙配对，无需在应用输入 Wi-Fi 密码。既有开发版本与一台 iPhone 的无线/USB 画面、触控和声音，以及 USB 暂停与重连已初测正常；这不等于新离线包已完成干净系统验收。
- **Windows USB：**包内 DLL 不替代 Apple Mobile Device Service、手机信任、权限和设备驱动配置。准备流程仍依赖 PowerShell 7 与相关 SDK 工具，并可能需要手动重插；不是完全即插即用。参见[驱动配置与恢复](../WINDOWS_USB_DRIVER.md)。
- **Linux x64 / ARM64：**Ubuntu 24.04 / glibc 2.39 基线，自带所选媒体依赖闭包。系统桌面、图形/音频驱动、BlueZ、NetworkManager、usbmuxd 和设备权限不捆绑；真机未验收。
- **macOS Intel / Apple Silicon：**macOS 15 GUI/核心预览，未公证。原生 RFCOMM、USB、网络适配未实现，不能完成接收端连接。
- **Android / HarmonyOS：**没有移动端安装包；桥接与系统适配仍待实现，见[后续移植方案](../MOBILE_PORTING.md)。

20 次连接循环、两小时稳定性、Siri/通话、音频设备切换与休眠恢复仍待验收。硬件解码、完整第二屏、P2P、AEC、停车视频和车辆扩展未交付。本轮离线打包不扩大既有[验收范围](../ACCEPTANCE.md)。

## English

This release changes the v0.1.0 external-runtime distribution into a **complete offline package preview**. Extract the entire archive and start its root `RustCarPlay.exe` on Windows or `./RustCarPlay` on Linux/macOS. Ordinary launch needs no Rust, Python, PowerShell or GStreamer installation and no manually entered certificate path. New package CI and environment validation are still in progress; check the actual Release and workflow results for available assets.

The thin root launcher configures only its child process. `app/` contains the desktop program and CLI; use `--cli` to select the latter. Media libraries/plugins are under `runtime/gstreamer/`, Windows USB user-space libraries under `runtime/usb/`, and fixed experimental authentication material under `resources/auth/`. Linux user-space connection libraries are bundled alongside the media dependency closure. Personal settings, pairings, caches and logs are generated in `.local/` and are not shipped.

**Experimental identity:** the fixed DiPlay v0.2.15 preview APK supplies this material, attributed upstream to public Carlinkit C2Air / Allwinner V821 firmware. It is not newly issued and is outside the source-code GPL. Public availability, extraction and choosing this preview distribution do not establish permission from the rights holder. Redistribution suitability and future iOS acceptance remain unresolved. `resources/auth/provenance.json` records the source and limitations; Git and Rust source archives exclude authentication private keys. See [third-party notices](../THIRD_PARTY_NOTICES.md).

- **Windows 11 x64:** start with LAN, the same Wi-Fi and OS Bluetooth pairing. No in-app Wi-Fi password is needed. Existing development builds passed initial wireless/USB video, touch and audio tests with one iPhone, plus USB pause/reconnect. This does not certify the new offline archive on a clean machine.
- **Windows USB:** still requires Apple Mobile Device Service, trust, permissions and device configuration. Preparation scripts retain PowerShell 7/SDK dependencies and may require a physical replug. Bundled DLLs do not make this fully plug-and-play; see [configuration and recovery](../WINDOWS_USB_DRIVER.md).
- **Linux x64 / ARM64:** Ubuntu 24.04 / glibc 2.39 baseline with the selected media dependency closure. Desktop services, graphics/audio drivers, BlueZ, NetworkManager, usbmuxd and device permissions remain OS prerequisites. No physical-device acceptance yet.
- **macOS Intel / Apple Silicon:** a non-notarized macOS 15 GUI/core preview. Native RFCOMM, USB and network adapters are missing; receiver connections are unavailable.
- **Android / HarmonyOS:** no mobile package yet; bridges and platform adapters remain planned. See the [porting roadmap](../MOBILE_PORTING.md).

Twenty connection cycles, two-hour stability, Siri/calls, audio device switching and sleep recovery remain unverified. Hardware decoding, full second-screen support, P2P, AEC, parked video and vehicle extensions remain unfinished. Offline packaging does not extend the recorded [device acceptance](../ACCEPTANCE.md).
